## 🧭 &nbsp;What it does

| | |
|---|---|
| **One-sentence architect** | “5 relaxed days in Lisbon with my partner — food, tiles and sunsets.” Voyara extracts dates, length, party, pace, budget and interests, geocodes the place and builds every day. |
| **Neighbourhood-clustered days** | Curated picks + live OpenStreetMap & Wikipedia places, ordered by a nearest-neighbour route so each day is walkable, with lunch and dinner where you'll actually be. |
| **Weather-aware swaps** | Every outdoor stop carries an indoor twin. A wet forecast swaps it in automatically; *Refresh forecast* re-plans later. |
| **Globe route planner** | Spin a real Earth, tap two to six places (reverse-geocoded, snapped to curated cities), and architect one multi-city trip with flights on travel days. |
| **One-tap booking** | Book the best-fit room for your party **and** a scooter / e-bike for the same dates — or a stay in every city of a route — with one confirmation. |
| **Hotels, done properly** | Live availability, add-ons, coupons, GST breakdown, reviews, wishlist, simulated payments and a boarding-pass PDF invoice with QR. |
| **Front desk & admin** | Staff check-in/out with pay-at-hotel collection; admin revenue charts, bookings, users & roles, payments, review moderation, coupons, add-ons and a hotel/room editor. |
| **Share & community** | Public trip links and a community feed to “make it mine”. A trip wallet stores tickets and visas. |

## 🧱 &nbsp;Architecture

```mermaid
flowchart LR
  U([Traveller]) -->|one sentence / globe stops| FE[React 19 · Vite · Router 7<br/>three.js · Leaflet]
  FE -->|JWT · REST| API[Express 5 · Zod · TypeScript]
  API --> DB[(MongoDB · Mongoose 9)]
  API --> AI{{Itinerary builder<br/>rules engine ± LLM}}
  AI --> LIVE[[Live data — no keys<br/>Nominatim · Photon · Overpass<br/>Open-Meteo · met.no · Wikipedia · ER-API]]
  AI -. optional .-> LLM[(Groq · Gemini · OpenAI)]
  API --> PDF[PDFKit + QR invoices]
```

| Layer | Stack |
|---|---|
| **Frontend** | React 19, TypeScript, Vite, React Router 7, Axios, hand-rolled CSS (Heart Aerospace–style “atmospheric” system: sky gradients, monumental 600-weight type, Jetstream `#001489`, zero radius), three.js (777 hero, globe), Leaflet maps, Lenis smooth scroll |
| **Backend** | Node 18+, Express 5, TypeScript, Mongoose 9, JWT Bearer, bcryptjs, Zod, Multer, PDFKit, QRCode, Nodemailer |
| **Database** | MongoDB — local, Atlas, or a built-in auto-seeded in-memory instance for dev |
| **Live data** | Nominatim + Photon (geocode), Overpass + Wikipedia geosearch (places, stays, rentals), Open-Meteo + met.no (weather), Wikipedia (overviews), ER-API (FX) — with time budgets, caching and an Overpass circuit breaker |

## 🚀 &nbsp;Quick start

```bash
# API → http://localhost:5001/api
cd backend
npm install
cp .env.example .env   # set MONGODB_URI and a JWT_SECRET (32+ chars: openssl rand -hex 32)
npm run dev
```

> No MongoDB installed? Set `USE_MEMORY_DB=true` in `backend/.env` (or run `npm run dev:memory`) — an in-memory database boots and **auto-seeds** on every start. An empty real database is also seeded on first boot.

```bash
# Web → http://localhost:5173
cd frontend
npm install
cp .env.example .env   # VITE_API_URL=http://localhost:5001/api
npm start
```

```bash
# Re-seed a real database at any time
cd backend && npm run seed
```

|---|---|---|
| `MONGODB_URI` | ✔︎ | Local or Atlas |
| `JWT_SECRET` | ✔︎ | ≥ 32 chars; the server refuses to start without it or with the example placeholder |
| `PORT`, `CORS_ORIGINS`, `PUBLIC_APP_URL` | | Defaults: `5001`, `http://localhost:5173` |
| `USE_MEMORY_DB` | | `true` for an auto-seeded in-memory DB |
| `GROQ_API_KEY` / `GEMINI_API_KEY` / `OPENAI_API_KEY` | | Optional LLM polish for themes & summaries |
| `GOOGLE_PLACES_API_KEY`, `TAVILY_API_KEY` / `EXA_API_KEY` | | Optional richer places & context |
| `SMTP_*` | | Optional booking emails (logged to console otherwise) |
